# Almaty daily PM2.5, 2021–2025

AirData.kz (Global Shapers Almaty Hub) publishes the city-wide daily PM2.5 concentration in µg/m³, averaged across geographic clusters. [Versioned upstream data and methodology](https://github.com/qazybekb/AirDatakz-OpenData/tree/5046605280f4a98e22a3e9bf6b06759db797d51f). AirData.kz shares these data under [CC BY-NC 4.0](https://creativecommons.org/licenses/by-nc/4.0/), with upstream provider terms also applicable. The project's MIT license covers code. Attribution and the noncommercial data license apply to this extract and its derived environmental tables and graphics.

We selected five complete calendar years and retained the original date, concentration, cluster count and station count. Dates are local calendar days. No interpolation, outlier removal or station weighting was added. The publisher already excludes suspect readings. Reporting coverage varied from 1 to 16 stations per day. AirData.kz flags uncertainty in some historical WAQI readings in Almaty. Treat shifts between years as descriptive, especially when the network changes.

The snapshot contains 1,823 of 1,826 calendar days. The three missing dates are 9–11 June 2022. Each observed day gets equal weight in the pooled seasonal means. Winter comprises January, February and December of each calendar year. Summer comprises June–August. The 915 observed shoulder-season dates remain in the snapshot and are excluded from this contrast. The season definition is a proxy for heating exposure. Daily wind, individual sensor records and actual heating dates are unavailable in this file.

Run `python src/environment.py --verify-source` from the repository to download the pinned compressed source and compare the extract to the committed CSV. The canonical CSV with LF line endings has SHA-256 `c2f60b86e663c8e4f6a1cee617835382d474ee5b3808426e0e3c19a11b26d137`. Ordinary notebook execution uses local files and requires no download. The optional `--collect` flag replaces only the 908-row benchmark log, alternating execution order with five warm-ups and thirty evaluation runs per implementation.
